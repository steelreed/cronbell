# CLAUDE.md — Cronbell

Monitoring for scheduled and background jobs, a Steelreed product. Read `DESIGN.md` first: it is the
specification, and behaviour changes start there. `ARCHITECTURE.md` explains how the server is built.

## Layout

| Directory | What | Toolchain |
|---|---|---|
| `server/` | Spring Boot 4.1 service: ping endpoint, management API, detector, notifier | Java 25 (`.java-version` pins Temurin 25 via jenv), Maven wrapper |
| `web/` | Dashboard SPA; the Docker build copies `web/dist` into the server's `static/`, `WebAppController` serves client routes | Node 26, Vite 8, React 19, TypeScript 7, TanStack Router/Query, Tailwind 4, shadcn/ui, Biome |
| `starter/` | (later) `cronbell-spring-boot-starter`, Java 17 baseline, Spring Boot 3 and 4 | Maven |

## Commands

```bash
make test       # server verify (tests + format check, needs Docker) and web lint, typecheck, tests
make format     # Spring Java Format for server/, Biome for web/
make docker     # image ghcr.io/steelreed/cronbell:dev (web bundled into the server)
```

`make test` must pass before every commit. CI (`.github/workflows/ci.yml`) runs the same plus an
image build and a DCO check; commit with `git commit -s`. `release.yml` publishes the image when
the maintainer pushes a `v*` tag: never create tags yourself.

## Conventions

- Maven groupId `com.steelreed`, packages `com.steelreed.cronbell.*`.
- The server is a modular monolith (`ARCHITECTURE.md`). Each package under
  `com.steelreed.cronbell.server` is a Spring Modulith module: `checks`, `pings`, `alerts`,
  `accounts`, `history`, `shared`, with a `package-info.java` listing its allowed dependencies. Only
  public types in the module package are its API; the rest goes in `<module>/internal`
  (package-private where possible), controllers in `<module>/web` with `@ManagementApi`. Other
  modules use the API or listen to its events, never its `internal` types or its tables.
- `ModularityTests` (Spring Modulith `verify()`, documentation in `target/spring-modulith-docs`) and
  `ArchitectureTests` (ArchUnit: pure `checks.internal.domain`, controllers in `web`, no field
  injection, no `Date`/`Calendar`) must pass. After a structural change, copy the generated
  diagrams to `docs/architecture` and update the Mermaid graph in `ARCHITECTURE.md`.
- Latest stable versions of every dependency and plugin (no milestones), Java 25 idioms: records
  for value types and DTOs, sealed types with pattern-matching `switch` for closed sets, text blocks
  for SQL, constructor injection, `final` fields, `Optional` only as a return type, no deprecated
  APIs (the build reports them).
- Licence: AGPL-3.0 for `server/` and `web/`; Apache-2.0 for `starter/`.
- English in code, comments, docs and commits. Talk to the maintainer in Vietnamese.
- Never add AI attribution (Co-Authored-By, "Generated with") to commits or PRs.
- Every change goes through a branch and a PR once the GitHub repo exists. The maintainer merges.
- Never read, print or commit secrets (`.env`, API keys, SMTP/Telegram tokens).
- shadcn/ui components live in `web/src/components/ui` and are generated code: add them with
  `npx shadcn@latest add <name>`, don't hand-edit unless needed.
- Web routes are TanStack file routes in `web/src/routes`; `routeTree.gen.ts` is generated by the
  Vite plugin (`npm run dev` or `npm run build`) and committed. Visible strings live in
  `web/src/lib/strings.ts`. The dashboard follows the locked Steelreed design
  (`../website/DESIGN-SYSTEM.md`): tokens in `web/src/index.css`, status as coloured text, no badges.
- Local dev: `make dev` (server on :8080, Vite on :5173 proxying `/api` and `/ping`); the first visit
  shows the setup page, or set `CRONBELL_ADMIN_EMAIL`/`CRONBELL_ADMIN_PASSWORD`.
